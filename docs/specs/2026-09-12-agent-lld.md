# Agent — Low-Level Design

**Date:** 2026-09-12
**Status:** Draft for review
**Scope:** Inside the agent — state schema, memory, sub-agents, tools,
human-in-the-loop, guardrails, budgets.
**Stack:** Python · LangGraph · Postgres checkpointer · Redis queue

---

## 1. Position in the System

The agent is the **final stage of every path**. Everything before it is ordinary,
testable, cheap software; the agent turns already-computed facts into language
and judgement.

```
   Events · Chat · Scheduled · Uploads
                  │
                  ▼
        ┌───────────────────┐
        │    ANALYTICS      │   deterministic — numbers computed here
        └───────────────────┘
                  │
                  ▼
        ┌───────────────────┐
        │      AGENT        │   reasoning, synthesis, narration
        └───────────────────┘
                  │
                  ▼
         predictions · alerts
```

It never computes a metric it could look up. If a correct answer can be derived
in Python, it is derived in Python and handed to the agent as a fact.

## 2. Invocation Modes

One runtime, four trigger shapes:

| Mode | Trigger | Sync | Cost profile |
|---|---|---|---|
| `event` | Event started / re-evaluation / stopped | No | Full |
| `candidate` | Auto-detected, unconfirmed | No | **Reduced** |
| `chat` | User question | **Yes, streaming** | Full |
| `scheduled` | Daily digest, weekly report, threshold alert | No | Full/batch |

`candidate` deliberately runs a cheaper subgraph — enough to ask *"are you
drinking?"*, not enough to burn a full orchestration on a detection that may be
wrong.

## 3. State Schema

The contract between every node and sub-agent. Typed strictly.

```python
class HealthAgentState(TypedDict):
    # ── identity — set once at entry, NEVER mutated ──────────────
    user_id: str
    session_id: str
    trigger: Literal["event", "candidate", "chat", "scheduled"]

    # ── what woke us ────────────────────────────────────────────
    event_id: str | None
    event_type: str | None
    window: tuple[datetime, datetime] | None

    # ── conversation ────────────────────────────────────────────
    messages: Annotated[list[AnyMessage], add_messages]

    # ── loaded context — populated by the context node ──────────
    user_profile: UserProfile
    safety_facts: SafetyFacts          # allergies, conditions, meds
    baselines: dict[str, Baseline]
    analytics: AnalyticsBundle         # from the deterministic layer
    retrieved_memories: list[Memory]

    # ── orchestration ───────────────────────────────────────────
    plan: list[SubTask]
    sub_results: Annotated[list[SubResult], operator.add]

    # ── output ──────────────────────────────────────────────────
    prediction: Prediction | None
    alerts: list[Alert]

    # ── control ─────────────────────────────────────────────────
    pending_approval: ApprovalRequest | None
    guardrail_flags: list[str]
    budget: BudgetState
```

### 3.1 Two Invariants

**`user_id` is written once at entry and never again.** It is the tenant
boundary. Enforce with a test that asserts no node mutates it; a violation is a
cross-tenant leak, not a bug.

**`analytics` is populated before any LLM runs.** The model reasons over
computed numbers rather than attempting to derive them from raw data. This is
principle P2 expressed in the state schema.

**`sub_results` uses `operator.add`** so parallel sub-agents can write
concurrently without clobbering each other.

```
          therapy  document  web    general   [analytics
           agent    agent  research  query     = TOOL, not agent]

                        ┌──────────────┐

                        └──────────────┘
```

### 4.1 Sub-Agent Design Rules

**Analytics is a tool, not an agent.** It is deterministic; wrapping it in an LLM
adds latency and error for nothing.

**Not every sub-agent needs an LLM.** The document agent is mostly retrieval; the
therapy agent is mostly structured queries. Use an LLM only where genuine
reasoning or synthesis occurs. Fewer LLM hops means faster, cheaper, and far
easier to debug.

**Independent sub-agents run in parallel.** Therapy, document, and web research
have no interdependencies.

| Sub-agent | LLM? | Primary work |
|---|---|---|
| Therapy | Light | Structured queries over `therapy_sessions`; correlation with event windows |
| Document | Light | Retrieval over `lab_results` + `documents`; LLM only for messy extraction |
| Web research | Yes | External evidence lookup; **must be sandboxed as untrusted input** |
| General query | Yes | Freeform reasoning, fallback routing |

## 5. Memory

Three tiers — genuinely different things, frequently conflated.

### 5.1 Short-Term — within a session

LangGraph **checkpointer backed by Postgres**, keyed by `thread_id`.

| Trigger | `thread_id` |
|---|---|
| Event | the event window |
| Chat | the conversation |
| Scheduled | the run |

This is what makes interrupts and resumption possible (§7), so it is not
optional.

### 5.2 Long-Term — across sessions

LangGraph `Store`, namespaced **per user**:

```python
namespace = ("memories", user_id)
```

> **Namespacing is the isolation boundary.** A retrieval cannot cross users
> because the user is part of the key. This is structural, not a matter of
> discipline.

Stores semantic facts with provenance and timestamp:

```
"lactose intolerant"                                    (source: user, 2026-03-02)
"reports poor sleep after evening alcohol"              (source: inferred, 2026-08-14)
"weekly sauna protocol since March"                     (source: events, 2026-09-01)
```

### 5.3 Reference Data — not memory

Genetics, lab results, therapy history, environment readings. Structured, exact
reads via the scoped context loader. **Do not put these in a vector store** —
they are not fuzzy and exact reads are required.

### 5.4 Retrieval Policy

| Data | Retrieval |
|---|---|
| Safety-critical (allergies, conditions, medications) | **Deterministic fetch — always included** |
| Semantic memories | Top-k by relevance to current event/question |
| Reference data | Exact scoped query |

> A vector store must never decide whether to mention a penicillin allergy.
> Safety facts are fetched, not searched.

**Anti-pattern:** retrieving everything for a user on every run. Context windows
fill, cost rises, and relevance drops.

### 5.5 Write-Back Loop

After a session completes, a **reflection step** runs a cheap LLM pass over the
transcript, extracting durable facts, deduplicating against existing memories,
and writing back.

Runs **asynchronously after responding** — the user never waits for memory
consolidation.

## 6. Tools

| Tool | Backed by | LLM sees |
|---|---|---|
| `get_event_analysis` | Analytics | before/during/after deltas vs. baseline |
| `get_sleep_summary` | Analytics | duration, stages, latency, trend |
| `get_trend` | Analytics | metric over range, vs. baseline |
| `get_recent_events` | Postgres | event history in window |
| `get_lab_results` | Postgres | structured extracted values |
| `get_therapy_history` | Postgres | sessions + outcomes |
| `get_genetics_context` | Postgres | relevant variants for this event type |
| `get_environment` | Postgres | temp, humidity, UV, AQI at event time |
| `search_memory` | Store (namespaced) | top-k semantic memories |
| `web_search` | External | **untrusted** — sanitised before use |

### 6.1 Tools Cannot Accept a User ID

Every data-access tool reads `user_id` **from state**, never from a parameter.

```python
# CORRECT — user_id comes from state, not the model
@tool
def get_sleep_summary(days: int, *, state: HealthAgentState):
    return analytics.sleep_summary(user_id=state["user_id"], days=days)

# FORBIDDEN — model could supply any id
@tool
def get_sleep_summary(user_id: str, days: int): ...
```

This makes cross-tenant access **impossible by construction** rather than by
discipline. It is the single most important rule in this document.

### 6.2 Analytics Parity

Agent tools call the **same analytics code** as the REST endpoints serving the
UI. If the tool and the endpoint diverge, a chart will show 6.2 hours while the
chatbot says 6.8, and trust in the product collapses. One implementation, two
callers.

## 7. Human-in-the-Loop

LangGraph's `interrupt()` pauses the graph and persists state via the
checkpointer. There is a subtlety specific to this architecture.

### 7.1 The Worker Must Not Block

**The agent runs in a background worker. Nobody is waiting on an HTTP
connection.** Holding a worker while a user decides would exhaust the pool within
minutes — and the user may never respond.

```
1. Agent hits interrupt()
   → checkpointer persists state
   → WORKER RETURNS AND IS FREED

2. Write row → pending_approvals (user_id, thread_id, question, options)

3. Mobile app sees it via Supabase Realtime → shows prompt

4. User taps → app updates the row

5. Webhook fires → enqueues resume job (thread_id + response)

6. ANY worker picks it up → resumes from checkpoint:
       graph.invoke(Command(resume=response), config={"thread_id": ...})
```

Step 6 may land on a **different worker** than step 1. That is fine precisely
because all state lives in the checkpointer, not process memory — the same
statelessness that enables horizontal scaling, paying off again.

### 7.2 Abandoned Approvals

People abandon prompts. `pending_approvals.expires_at` is mandatory:

- On expiry: mark the session closed.
- **An abandoned approval must never leave a half-finished prediction visible to
  the user.**

### 7.3 When to Interrupt

Every prompt costs user attention. A health app that constantly asks permission
becomes noise people dismiss reflexively — which destroys the value of the
prompts that actually matter.

Reserve interrupts for genuinely consequential moments. Routine analysis never
interrupts.

## 8. Guardrails

Layered, cheapest first.

### 8.1 Input

| Check | Detail |
|---|---|
| Identity | `user_id` taken from the **verified** webhook payload only |
| Injection | Sanitise all user-supplied text **and uploaded documents** — a malicious PDF is a real vector |
| Allowlist | `event_type` validated against known types |
| Untrusted external content | Web search results treated as data, never instructions |

**The scoped context loader** is the single module through which all user data is
read. Every query is scoped by `user_id`. No agent tool constructs a raw query
itself. This gives exactly one auditable place where tenant scoping can go wrong.

> This matters because the agent uses **service-role credentials that bypass RLS
> by design**. RLS protects the mobile app; it does not protect the agent.
> Application code is solely responsible for tenant isolation.

### 8.2 Tool Level

Covered in §6.1 — tools cannot accept an arbitrary user id.

### 8.3 Output — Medical Safety

**Deterministic rules that run after the LLM and before anything reaches the
user.** Never let the LLM be the only thing deciding whether output is safe;
a rules layer catches what prompting misses.

| Rule | Action |
|---|---|
| Diagnostic language | Block |
| Medication or dosage advice | Block |
| Treatment prescription | Block |
| Clinically dangerous values detected | Force escalation language |
| Missing uncertainty on a correlational claim | Rewrite |

### 8.4 Budget

Agents loop. Without hard caps, one pathological session can cost hundreds of
dollars unnoticed.

| Cap | Scope |
|---|---|
| Max tokens | per session |
| Max tool calls | per session |
| Max wall-clock | per session |
| Max sub-agent depth | per session |
| Max LLM calls | per session |

Exceeding a cap terminates cleanly with a partial result — never a silent hang.

## 9. Session Isolation

**VM-per-session isolation is explicitly not used.** Full rationale in Platform
HLD §7.1; summarised here because it is an agent-level decision.

Firecracker microVMs (as in AWS Bedrock AgentCore) solve **untrusted code
execution**. Our tools are database queries, web search, retrieval, and LLM calls
— bounded operations against systems we control. A microVM protects against a
malicious *process*; it does nothing about the risk we actually have, which is
**user A's data appearing in user B's context** — a logic bug no VM catches.

What is used instead:

- Stateless workers — context loaded fresh per job, nothing retained
- A single audited scoped context loader
- Per-job context objects, never process-global
- Namespaced long-term memory

**Revisit when:** a tool executes LLM-generated code. That is genuine untrusted
execution needing a real sandbox — E2B, Daytona, Modal, or Vercel Sandbox behind
an API call, with the agent remaining on Railway. Add it when code execution is
added, not before.

## 10. Observability

Every log line, span, and metric carries `user_id`, `session_id`, and
`event_id`.

| Tracked | Why |
|---|---|
| Tokens per session, by mode | Cost regressions are invisible until the bill |
| Tool calls per session | Detects loops |
| Sub-agent latency | Finds the slow path |
| Guardrail triggers by rule | Safety monitoring |
| Interrupt rate, approval abandonment | Prompt fatigue signal |
| Every data access | Audit log — regulatory necessity |

## 11. Failure Modes

| Failure | Consequence | Mitigation |
|---|---|---|
| Worker dies mid-run | Session lost | Checkpointer; resume from last step |
| LLM API outage | No output | Retry with backoff; fall back to deterministic analytics summary |
| Sub-agent hangs | Session stalls | Per-sub-agent timeout; proceed with partial results |
| Infinite tool loop | Runaway cost | Budget caps (§8.4) |
| Injected instruction in a document | Agent misbehaves | Input sanitisation; untrusted content never treated as instruction |
| Guardrail false positive | Useful output blocked | Log every block with the triggering rule; review regularly |
| Duplicate webhook delivery | Duplicate predictions | Idempotency key `(event_id, status, attempt_reason)` |
| Half-finished run | Confusing partial UI state | Predictions written transactionally at PERSIST only |

## 12. Testing Strategy

| Layer | Approach |
|---|---|
| Analytics | Unit tests — deterministic, exhaustive. Highest value per effort. |
| Tools | Contract tests; assert `user_id` scoping on every tool |
| **Tenant isolation** | Dedicated suite: attempt cross-user access through every tool and assert failure |
| Guardrails | Fixture corpus of unsafe outputs; assert blocks |
| Graph | Recorded LLM fixtures; assert routing and state transitions |
| HITL | Integration test: interrupt → worker released → resume on a *different* worker |
| Budgets | Assert clean termination at each cap |
